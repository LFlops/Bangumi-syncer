## 一、PR description（中文版）

```markdown
## 概述

为「AI 追番总结」任务新增**记忆上下文能力**（本地设计规格 Phase 2.0.1–2.0.3 的实现）。
每次成功总结后会提炼一行摘要 + 全文，写入本地 SQLite 记忆库（含 FTS5 全文索引与归档冷表）；
后续执行时把最近的历史摘要与「窗口重叠标注」注入提示词；记忆随任务改名/删除联动迁移与清理。

本分支基于正在合并中的 `support_anthropic`（LLM 提供方支持）之上继续开发，为**纯增量功能**，
`memory_enabled` 默认关闭，存量行为完全不变。`specs/` 设计文档按仓库惯例**不随分支入库**（本地保留）。

## 功能与动机

- **使用场景**：现有「AI 追番总结」任务是无状态的——每次执行 LLM 只看到本次时间窗口的记录，
  无法引用上一次总结的结论；且 `lookback_days` 回溯多天时，相邻两次执行的范围重叠，
  相同剧集（或同一集）会被重复叙述。
- **写入（2.0.1）**：摘要 + 全文与「剧集消费标记」（`sync_records.consumed_run_id`）
  **同一事务原子写入**；失败路径不写记忆（LLM 空响应跳过、摘要失败规则截断兜底），
  无 `outcome='failed'` 无效条目。
- **读取（2.0.2）**：`memory_enabled` / `memory_limit` 每任务独立配置（Web 表单开关 + 条数，
  开关关闭时条数禁用）；`## 历史执行上下文` 注入 system prompt（最近 N 条摘要 + 今日标题
  FTS5 关键词召回、按 run_id 去重）；消费标记**精确到集**识别窗口重叠，并在提示词中标注
  「已在上次总结中覆盖，可简述或跳过」。
- **生命周期（2.0.3）**：任务改名 → 记忆主表+归档表同一事务迁移；任务删除 → 记忆+归档+
  消费标记同一事务清空（不留孤儿数据/悬挂引用）。
- **错误处理（2026-08-20 定稿）**：总结过程**任何阶段失败都通知用户**，按阶段
  （query / chat / store）区分文案；唯一例外是通知投递本身失败不二次通知（投递层重试/告警兜底）。

## 测试

- 全量：**3553 passed / 5 xfailed**；Ruff check + format 全部通过。
```

## 二、Issue 正文（中文版）

### 标题建议

> Feature idea：AI 追番总结任务的「记忆上下文」增强（附参考实现）

### 正文

```markdown
## 动机

现有的「AI 追番总结」功能是**无状态**的：每次执行 LLM 只看到本次时间窗口内的记录。
由此带来两个实际痛点：

1. **上下文不连续**——连续多日执行时，无法引用上一次总结的结论（比如上次已经追到
   某番 S1E10），输出容易重复介绍。
2. **窗口重叠**——`lookback_days=7` 时相邻两次执行的范围重叠 6 天，相同剧集/同一集
   每天都会被重复叙述。

此外，任务改名/删除时存在孤儿状态，部分失败路径会静默吞错。

## 我做了什么（参考实现见分支 `support_memo`）

基于 SQLite 实现了一套「写入 → 读取 → 清理」完整闭环的每任务记忆系统：

- **写入**：每次成功总结后 LLM 提炼一行摘要（+ 全文留档），写入 `agent_working_memory`；
  写入与「剧集消费标记」（`sync_records`）同一事务原子提交。失败不写记忆
  （空响应跳过、摘要失败规则截断兜底）。
- **读取**：`memory_enabled` / `memory_limit` 每任务配置（Web 表单开关 + 条数，
  默认**关闭**，存量行为零变化）。最近摘要 + 关键词（FTS5）召回注入 system prompt 的
  `## 历史执行上下文`；消费标记精确识别窗口重叠并标注「已覆盖可简述」。
- **清理**：任务改名迁移记忆；任务删除同一事务清空记忆 + 归档 + 消费标记。
- **错误处理**：任何阶段失败都会通知用户，按阶段（query / chat / store）区分文案；
  唯一例外是通知投递失败不二次通知。
- **质量**：全量 3553 测试通过（+68 项记忆相关），Ruff 全绿。
  设计文档在本地未入库的 `specs/` 目录（PR 描述里有浓缩版说明）。

## 想征询维护者的意见

1. 这个「记忆上下文」方向对项目是否有价值、值得合入上游？
2. 若值得，后续哪一步更契合 roadmap：工具调用（2.1）、LLM 层统一重构（2.2）、
   用户反馈记忆（2.3）、失败诊断 Agent（Phase 3，含全文索引增强）？
3. 记忆是否需要扩展到非总结类任务（如飞牛 feiniu）？是否需要用户可见的记忆管理界面
   （查看/编辑/导出）？

如果需要调整范围，我可以把它拆成更小的 PR 再提交。
```
