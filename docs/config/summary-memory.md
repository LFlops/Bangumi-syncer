# 🧠 AI 追番总结 · 记忆功能

「AI 追番总结」任务默认**无状态**：每次执行时 LLM 只看到本次时间范围内的观影记录，
不会参考上一次总结的内容。开启**记忆功能**后，系统会把每次总结的摘要保存到本地，
并在后续执行时注入提示词，让总结更连贯、可引用历史结论。

## 使用场景

- **上下文延续**：今天总结时会看到昨天的结论，例如上次说"芙莉莲追到 S1E10"，
  这次就能接着自然过渡而不重复介绍。
- **窗口重叠**：任务按 `lookback_days` 回溯多天（如 7 天）时，相邻两次执行的
  查询范围会重叠（2-8 天 ∩ 1-7 天）。开启记忆后，同一集的记录会精确识别为
  "已在上次总结中覆盖"，并在提示词中标注"可简述或跳过"，避免重复叙述。
- **记忆生命周期**：改名任务 → 历史记忆一并迁移；删除任务 → 记忆、归档与消费标记
  在同一事务内清空，不留孤儿数据。

## 如何开启

「配置管理 → AI 追番总结」任务卡片中新增两项（对应 `config.ini` 的 `[summary-*]` 段）：

- **记忆开关**（`memory_enabled`，默认 `False`）：开启后注入历史上下文，并每次总结
  成功后写入新记忆。**默认关闭**，不影响存量行为。
- **记忆条数**（`memory_limit`，默认 `5`，最小值 1，仅开关打开时生效）：注入到提示词
  中的历史摘要条数。开关关闭时该输入框禁用。

> **每任务独立**：记忆按任务隔离，没有全局开关。多用户场景下记忆为任务级混合
> （与任务级混合总结一致）；如需按用户隔离，请为每个用户单独建任务。

## 记忆存在哪里

- 本地 SQLite（`data/sync_records.db` 的 `agent_working_memory` 表 + FTS5 全文索引，
  超量自动归档到 `agent_working_memory_archive`）。
- **不会**发送到站内信/外部通知渠道，仅用于提示词注入。
- 摘要由 LLM 生成（一行短摘要 + 本次全文留档），失败路径不写入无效条目。

## 出错时的行为

总结过程**任何阶段失败都会通知你**，并按阶段区分提示文案，方便定位问题环节：

| 失败阶段 | 通知类型 | 提示重点 |
|---|---|---|
| 查询/构建（query） | `summary_job_failed` | 请检查任务配置 |
| LLM 调用（chat） | `summary_llm_failed` | 请检查 API 地址和密钥 |
| 记忆写入（store） | `summary_job_failed` | 记忆写入失败，下次将重新总结 |
| 通知投递（notify） | 不二次通知 | 投递层问题走通知重试/告警兜底 |

## 注意事项

- 关闭记忆开关 = 不注入也不写入（读写一致），重新开启后视为从未总结过（消费标记
  不追踪关闭期间的观看记录）。
- 删除任务会**彻底清空**该任务的记忆（含用户偏好类条目）；想保留历史再重建，
  可先给任务改个名再新建。
